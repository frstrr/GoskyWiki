# 用AI更有野心的四维方法

## TL;DR

多数人用 AI 偏保守（问答、润色、填模板）。更有野心的用法是按 **速度 / 高度 / 深度 / 广度** 抬目标：盯最终结果而非子任务；逼模型用专家级工具与原始数据；引入跨领域方法；并用可运行的外部验证替代自评。一句口诀：**把目标定得「不合理」，再告诉模型——这完全合理，继续试。**

## Key points

- **高度**：问「目标背后的目标」；若做完还要开会，就再往上提一层。
- **深度**：专家工具 + 原始材料 + 不合理目标 + 挑战假设 + 外部验证。
- **广度**：名词改动词，再按领域方法做事（避免空角色扮演）。
- **速度**：提效已成熟，不必过度设计用法。
- **前提**：模型能操作电脑、装软件、访问数据（MCP/连接器等），野心才落得了地。

## Notes

### 四维一览

| 维 | 要解决的问题 | 典型动作 |
|----|--------------|----------|
| 速度 | 同样产出太慢 | 用 AI 加快编码/写作等；用法已成熟 |
| 高度 | 卡在子任务清单 | 改问最终结果与机制设计 |
| 深度 | 表面专业、实际浅 | 专家工具链 + 原始数据 + 外部检验 |
| 广度 | 解法空间太窄 | 跨领域视角；名词→动词打开问题空间 |

### 高度：抬抽象层

模板式派活（「把数字填进 PPT」）会把模型锁在你当前设想的最优路径上。改问：

1. 这个季度发生了什么、为什么、该采取什么行动？（先理解，再填表）
2. 眼下最迫切的三项决策是什么？各方支持/反对理由？
3. 有没有比「季度 PPT」更能早发现问题、调配资源的机制？用历史数据证明，并与现有流程并行验证。

工程类类比：从「修这一个崩溃」升级到「保证应用持续无崩溃」——同时补齐崩溃报告、版本↔提交映射、多端复现权限。

### 深度：专家级做透

常用五连招：

1. **工具升级**：拒绝「像专家说话」却仍用 Markdown 表；要求数据库、统计模型等专家工具（可让模型自己列出该用什么）。
2. **不合理目标**：10s→5s 改为要求 0.2s；模型喊难就反复强调「可解，再试」。
3. **挑战结论**：把已有判断交回原始数据复现，并找反例。
4. **挖盲点**：在深入数据后要求找新信号，用未见数据验证。
5. **外部评判**：跑真代码、用新数据测预测；禁止模型给自己打分当验收。

可复用「深度改写」提示骨架：

```text
我希望把这项任务做得更深入，而不是扩大范围。改写任务前先完成：
1) 顶尖专业人士还会做哪些我还没要求的事；
2) 他们会从哪些最原始材料入手；
3) 他们会用哪些具体方法与工具；
4) 除了你我之外，还有什么能证明结果正确。
然后据此改写我的提示词。
```

### 广度：跨领域重组

- **名词→动词**：把交付物名称改成要达成的人际/决策效果，更容易看出该请哪些领域方法进来。
  - 例：「做汇报 PPT」→「30 分钟内说服忙碌听众接受因果解释并在不确定时决策」。
- **组「虚拟跨领域团队」**：分析、叙事、编辑、动效、怀疑论、审计等视角有用；但应 **直接采用该领域方法做调查/制作**，避免只让模型「扮演某角色聊天」。

### 与自我效能感的关系

AI 能力快速跃迁时，瓶颈常在「人认为什么可能」。清晰且有挑战性的目标，通常优于模糊的「尽力而为」。允许试错、看见他人突破先例，有助于抬高自我效能感，从而敢给模型更高目标。

## Failure modes

- 只加专业黑话，不换工具与数据源。
- 目标抬高但没有复现/验证权限，模型无法闭环。
- 让模型自评当验收。
- 「跨领域」沦为角色扮演，产出更怪却不更好。
- 对创作类任务硬套「抬高度」——文中认为高度法对最终结果型任务更有效，创作适用性相对有限。
